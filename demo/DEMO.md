# Internet Demo Script

Use this file as the spoken and terminal flow for the final demo. The preferred public setup is:

- VPS runs Docker Compose.
- Caddy exposes `https://$PUBLIC_DOMAIN` on ports 80/443.
- Caddy proxies to Kong on the private Docker network.
- Keycloak, Vault, OPA, Grafana, Loki, PostgreSQL, and Redis are not exposed publicly.

## Before the demo

1. On the VPS, set `.env` from `deploy/internet.env.template`.
2. Point DNS `A` record for `PUBLIC_DOMAIN` to the VPS public IP.
3. Open firewall ports 80 and 443 only, plus SSH.
4. Bootstrap the stack:

```bash
bash scripts/bootstrap-internet-demo.sh
```

5. Run checks:

```bash
python -m pytest -q
bash scripts/test-opa.sh
bash scripts/internet-smoke-test.sh "https://$PUBLIC_DOMAIN"
```

6. Open Grafana with an SSH tunnel:

```bash
ssh -L 3000:127.0.0.1:3000 <user>@<vps-ip>
```

Then open `http://localhost:3000`.

## Live demo flow

### 1. Show the public API is online

```bash
curl -i "https://$PUBLIC_DOMAIN/api/v1/resources"
```

Expected: `401 Unauthorized`.

Message to say: the Internet entrypoint is Kong/Caddy; unauthenticated traffic is rejected before it reaches services.

### 2. Show Keycloak-issued tenant claims

```bash
TOKEN="$(bash scripts/get-token.sh alpha-user@example.com "$KEYCLOAK_LAB_USER_PASSWORD")"
python - <<'PY'
import base64, json, os
token = os.environ["TOKEN"]
payload = token.split(".")[1]
payload += "=" * (-len(payload) % 4)
claims = json.loads(base64.urlsafe_b64decode(payload))
print(json.dumps({
    "sub": claims.get("sub"),
    "tenant_id": claims.get("tenant_id"),
    "aud": claims.get("aud"),
    "roles": claims.get("realm_access", {}).get("roles", []),
    "exp": claims.get("exp"),
    "jti": claims.get("jti"),
}, indent=2))
PY
```

Expected: token contains `tenant_id`, `aud=saas-api`, and tenant role.

### 3. Tenant alpha can access its resources

```bash
curl -k -i "https://$PUBLIC_DOMAIN/api/v1/resources" \
  -H "Authorization: Bearer $TOKEN"
```

Expected: `200 OK`.

### 4. BOLA attempt is blocked

Run:

```bash
bash demo/demo-script.sh "https://$PUBLIC_DOMAIN"
```

Important lines to show:

- Beta reads Alpha resource -> `403`.
- Loki/Grafana contains `security.bola_attempt`.

### 5. Gateway policy and WAF-lite

Show:

- tenant user hitting `/api/v1/admin/tenants` -> `403`.
- non-JSON write -> `415`.
- repeated resource requests -> `429`.

These are generated by `demo/demo-script.sh`.

### 6. Stripe webhook forgery

Show:

```bash
curl -i "https://$PUBLIC_DOMAIN/webhooks/stripe" \
  -H "Content-Type: application/json" \
  -H "Stripe-Signature: t=123,v1=forged" \
  -d @demo/synthetic-data/stripe-payment-succeeded.json
```

Expected: `400 Bad Request`.

Message to say: inbound Stripe webhook uses Stripe HMAC because Stripe controls the sender signature. ML-DSA is used for our outbound application-layer signatures.

### 7. ML-DSA application-layer signing

Run:

```bash
python tests/benchmarks/benchmark_mldsa.py --iterations 20
```

Expected: key/sign/verify metrics and ML-DSA-65 sizes.

Message to say: this is not PQC TLS. It is application-layer authenticity for service tokens and outbound webhooks.

### 8. Observability evidence

In Grafana:

- Open `NT219 Security Events`.
- Query `security.bola_attempt`.
- Query `security.invalid_webhook_signature`.
- Show alert rules: `BOLAAttemptDetected`, `StripeWebhookFailure`, `RateLimitViolation`.

## Closing message

This is a security-focused prototype for a small multi-tenant SaaS. It demonstrates gateway enforcement, OIDC JWT claims, OPA authorization, tenant isolation, BOLA detection, Vault-managed signing material, ML-DSA application-layer signatures, Stripe webhook verification, security testing, and observability. Production limitations are documented separately: Vault dev mode, Compose not HA, upstream TLS verification not full mTLS, and Keycloak Organizations simulated with attributes.
